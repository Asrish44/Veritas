**Veritas** is an evidence-grounded research assistant and document analysis platform that operates **100% locally** on your machine. Every answer generated by the assistant is cross-referenced, verified against retrieved passages, and accompanied by strict citable evidence references `[n]` linking directly to the source text.

---

## Key Features

### 1. 100% Local Inference with Qwen3-14B
- Direct integration with local **Ollama** running the **Qwen3-14B** reasoning model.
- **Zero Cloud API Dependencies**: All inference, extraction, and synthesis happen entirely on-device, preserving research data privacy.
- Supports strict structured JSON outputs and think-token stripping.

### 2. Modern Two-Factor Authentication (2FA) Workflow
- **Registration**: User signs up with name, email, and password.
- **Bcrypt Hashing**: Passwords securely hashed with `bcrypt` (cost factor 10-12).
- **Strict Email Uniqueness**: Enforced via SQLite database constraints.
- **Two-Step Login Flow**:
  - *Step 1*: Validates credentials via bcrypt. Valid credentials **do not** issue a session token immediately.
  - *Step 2*: Server generates a secure 6-digit numeric OTP with a **10-minute expiry (TTL)** and dispatches it via Nodemailer (with server console fallback for local development).
- **OTP Verification & Replay Prevention**:
  - Consumes and immediately deletes the OTP record upon verification to block replay attacks.
  - Signs and returns a JWT containing user identity and role.
  - Rate-limited resend endpoint (`/api/send-otp`) with cooldown guards (HTTP 429).
- **Frontend UX**:
  - Smooth animated transition to a segmented 6-digit input.
  - Auto-focuses next digit on type, backspace navigation, arrow navigation, paste distribution across all 6 inputs, and cooldown timer.
  - JWT stored in `sessionStorage` and attached as `Authorization: Bearer <token>` on all requests.

### 3. Private Admin Console (Link-Only Access)
- Accessible **strictly by secret authorized link** (`/admin?token=admin-secret-access-link-cbit-2026`).
- Direct visits without the token trigger an **Access Denied (HTTP 403)** screen with a security lock.
- **Live Model Dashboard**: Real-time status of Ollama, active Qwen3-14B weights, memory usage, and an interactive live inference tester.
- **User Directory**: View all registered user accounts and toggle roles (Admin $\leftrightarrow$ User).
- **Document Repository**: Inspect all ingested documents, chunk counts, hashes, and manage deletions.
- **Admin Link Manager**: Quick copy button for authorized sharing.

### 4. Universal Multi-Format RAG Ingestion
Supports all primary research formats:
- **`.docx` / `.doc`**: Word document extraction using `mammoth`.
- **`.pdf`**: Page-by-page parsing using `pdf-parse`.
- **`.md` / `.txt` / `.csv` / `.json` / `.html`**: Structured parsing and pagination.
- **Hybrid Retrieval**: Combines **BM25 lexical search** with **BGE-Small vector embeddings** (`Xenova/bge-small-en-v1.5`) using Reciprocal Rank Fusion (RRF).
- **Evidence Reference Identifiers**: Passages mapped to stable citable references: `{hash8}::p{page}::c{idx}`.

## Getting Started

### Prerequisites
- **Node.js**: v18.0.0 or higher (v20+ recommended)
- **Ollama**: Installed and running locally ([Download Ollama](https://ollama.com/))
- **Model**: Pull the Qwen3 14B model:
  ```bash
  ollama run qwen3:14b
  ```

### Installation

1. **Clone the repository**:
   ```bash
   git clone https://github.com/Asrish44/Veritas.git
   cd Veritas
   ```

2. **Install dependencies**:
   ```bash
   npm install
   ```

3. **Configure Environment Variables**:
   Copy `.env.example` to `.env`:
   ```bash
   cp .env.example .env
   ```
   *(Ensure `DATABASE_URL`, `JWT_SECRET`, and `ADMIN_SECRET_KEY` are defined. SMTP can remain blank for console fallback during development).*

4. **Initialize Database**:
   ```bash
   npx prisma db push
   npx prisma generate
   ```

5. **Start the Development Server**:
   ```bash
   npm run dev
   ```
   The app will be running at [http://localhost:3000](http://localhost:3000).

## 2FA Email Configuration (SMTP)

To send real OTP emails to users via Nodemailer, configure your SMTP credentials in `.env`:

### Brevo (Recommended):
```env
SMTP_HOST=smtp-relay.brevo.com
SMTP_PORT=587
SMTP_USER=your-brevo-login-email@smtp-brevo.com
SMTP_PASS=your-generated-brevo-smtp-key
SMTP_FROM="Veritas Security" <your-verified-email@domain.com>
```

### Gmail:
1. Enable 2-Step Verification in Google Account.
2. Generate an App Password at [https://myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords).
3. Set in `.env`:
   ```env
   SMTP_HOST=smtp.gmail.com
   SMTP_PORT=587
   SMTP_USER=your-email@gmail.com
   SMTP_PASS=your-16-character-app-password
   SMTP_FROM="Veritas Security" <your-email@gmail.com>
   ```

*(If SMTP variables are left empty, the server automatically outputs the 6-digit OTP to the terminal console for seamless local development).*

## API Reference

| Endpoint | Method | Description |
| :--- | :--- | :--- |
| `/api/auth` | `POST` | User registration (`action: "register"`), Step 1 login (`action: "login"`), and session verification (`action: "me"`) |
| `/api/verify-otp` | `POST` | Verifies 6-digit OTP, invalidates/deletes OTP code from database, and issues signed JWT |
| `/api/send-otp` | `POST` | Rate-limited endpoint to resend OTP code with cooldown protection |
| `/api/papers` | `POST` | Multipart upload for `.docx`, `.pdf`, `.txt`, `.md`, `.csv`, `.json` with automatic chunking & vector embedding |
| `/api/papers` | `GET` | Lists all indexed documents and passage counts |
| `/api/chat` | `POST` | Evidence-grounded Q&A against indexed documents with source citations using Qwen3-14B |
| `/api/admin` | `GET/POST` | Protected admin metrics, user management, and live model testing (requires `?token=...`) |
